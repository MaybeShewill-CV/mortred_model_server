## 缺陷

`depth_vitl14` 与 `metric3d_512` 的 CPU 数值黄金没有提交。权重存在，加载和推理都完成了，失败点是缺黄金，没有走缺权重跳过。

最短复现，工作树根目录，不设置 `MORTRED_UPDATE_GOLDEN` 与 `MORTRED_CI_REQUIRE_WEIGHTS`：

`LD_LIBRARY_PATH=<工作树>/3rd_party/libs:<工作树>/3rd_party/_lib ./_bin/model_golden_test --gtest_filter=model_golden.depth_vitl14`

退出码 1。ORT 已打印 `input:f32[1,3,518,518]` 和 `output:f32[1,1,518,518]`，随后 `test/model_golden_registry.h:756` 失败，文案是 `golden missing, run with MORTRED_UPDATE_GOLDEN=1: depth_vitl14`。`test/golden/depth_vitl14.json` 不在树里。

把过滤换成 `model_golden.metric3d_512` 同样退出码 1。ORT 已打印 `input_image:f32[1,3,512,1088]`、`prediction` 和 `confidence`，文案是 `golden missing, run with MORTRED_UPDATE_GOLDEN=1: metric3d_512`。`test/golden/metric3d_512.json` 不存在。

## 不适用

- 正确 catalog id、错误 id、未就绪模型：方案没有 HTTP 变化。
- 空输入、极端尺寸、通道或色彩与预处理不符：验收标准没有这条。
- HTTP 输出结构、错误码、超时、参数缺失：契约没有变化。缺权重和比较失败已在验收 4 至 10。
- 产品 TensorRT 与 CPU 的同规则数值比较：方案明确不做，留给 P1-12。验收 11 只看测试列表。
- 旧黄金全量复跑：方案只要求四条 fingerprint 里破坏一条。已跑 `bisenetv2_segmentation`。

## 残余风险

- 16 条通过是分进程得到的。19 条放在同一个进程里的 `NUMERICAL_PASSED` 没有跑。
- `weights/object_detection/yolov8/yolov8s.onnx` 这个文件当前不存在。`conf/ci/yolov8_onnx_hosted.toml` 仍指向它。三个新用例没有用它。旧的 `model_golden.yolov8_detection` 这次没有复跑。
- `3rd_party/_lib` 这个目录不存在。`libmodels.so` 由二进制的 `_lib` RPATH 找到，其余库来自 `3rd_party/libs`。
- `depth_vits14` 乘 2 后的平均相对误差是 0.465。门按 `depth error` 和 `0.02` 失败，比较函数工作正常。
