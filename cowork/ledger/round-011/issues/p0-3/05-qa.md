## 不适用
- 正确 catalog id、错误 id、未就绪模型：本条只改这两个 id 的后处理返回值。错误 id 与未就绪模型的 HTTP 行为不在验收 1 至 8。白盒已核对 `yolov7` 与 `yolov7x` 的工厂入口都调用 `create_yolov7_detector`。
- 空输入、极端尺寸、通道或色彩与预处理约定不符：letterbox 几何无效仍是 `model input empty`，方案写明不改预处理。
- 输出框坐标、mask、类别分数的形状和值域：方案不要求权重、GPU、TensorRT engine 或 golden。验收 7 只要求成功解码时 HTTP 200、status 0，且 `data` 不是 JSON null。
- 超时、参数缺失、鉴权与其它错误码：`docs/api-contract.md` 里 status 6 对应 HTTP 500，status 5 落在「others」的 HTTP 500。这两档已由验收 1 至 6 覆盖。超时、422、401 不在本条改动面。
- 后端数值一致：方案写明 cpu profile 不链 TensorRT，契约测在 `full-cpu` 上运行，不要求 TRT 比较。
- 已有 golden 与全量 CI：方案不要求重跑 golden。本次只跑 `YoloV7OutputContract`。

## 残余风险
验收 7 的三个头是有限全零 f32，成功路径的框数为 0。它证明 status 0 且 `data` 为 JSON 数组，不比较框坐标。`output`/`518`/`532` 三个名字同时对齐之后的 dtype、通道、buffer 和非有限值失败仍走原契约失败分支，本条未重跑。
