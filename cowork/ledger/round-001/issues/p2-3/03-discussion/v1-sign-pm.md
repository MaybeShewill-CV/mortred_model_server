# 第3步确认

- 问题: P2-3
- 方案版本: v1
- 结论: 不同意
- 条件: 同一次启动里，对 libface 这个直接子进程的跟踪要覆盖从 fork 返回到随后那次 exec 之前，该 pid 出现在这段记录中，库函数名没有 prctl、execvp、setenv，带绝对路径的 execve 只作为这段终点；只读到 exec 之后同一 pid 的调用不算通过。本次 nvidia-smi 探测有输出时，那个直接子进程用同一段判定，路径不必以 /nvidia-smi 结尾。
- 理由: 验收标准 2 和自测脚本把跟踪写到启动时打开的日志文件。模型子进程在 fork 之后先关掉编号不小于 3 的文件描述符，再调用 prctl 和 execve，跟踪用的文件描述符在这两次调用之前已被关掉，日志读不到锁定句要看的那一段。该 pid 若不出现，第 2 条不通过；若只出现 exec 之后的调用，又没有那条 execve 时，脚本会把这些调用整段算进窗口。两种结果都确认不了「fork 返回之后、随后的 exec 之前没有 prctl、execvp、setenv」。验收标准 4 在采样日志为 online 或 utilization N/A 时，还要求路径以 /nvidia-smi 结尾。锁定句只要求探测有输出，或按现有三句标明失败；附录写明不把「nvidia-smi 改为带绝对路径的 execve」写成通过条件。验收标准 1 和 3 能核对配置与 running，替代不了这段跟踪。
