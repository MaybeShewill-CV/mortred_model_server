## 不适用
- 错误 catalog id、未就绪模型：本条只要求正确 id `libface` 一次进入 running，方案不测错误 id，也不拉起第二个模型。
- 空输入、极端尺寸、通道与色彩、坐标、mask、类别分数：方案不跑推理，也不跑 `http_infer_rps.py`。
- 管理 API 的错误码、缺参、gateway token 拒绝和停止顺序：方案写明不写入 P2-3 结论。gateway 本次不设 metrics token，允许跟踪里没有 gateway 子进程。
- 多后端同一输入对照：方案不改 TensorRT execution context，不要求后端对照。
- 推理 golden：不覆盖 fork 到 exec 的库函数窗口，方案也不拿 golden 当通过条件。
- `cli_app.cpp` 的 `fork` 与 `execvp`：不在这次 supervisor 启动路径上，方案明确不改、不验收。

## 残余风险
- 跟踪只挂钩 libc 的 `prctl`、`execvp`、`setenv`、`execve`。`syscall(SYS_prctl)` 不会出现在日志里，这次没有另测父进程退出后子进程是否收到 `SIGINT`。方案规定日志里没有 `syscall` 不影响通过。
- 这条库函数跟踪不在 CI 里。`occupancy_gate_unittest` 编进 test 目标，这次没有重跑 CI。
- 每个直接子进程在终点行之后还有 1 条跟踪。按方案该行不计入窗口，报告没有展开它的函数名。
