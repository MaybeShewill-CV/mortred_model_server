## 行为变化

模型子进程和同一函数拉起的 gateway 子进程，仍在关掉 fd 3 及以上之后、`execve` 之前设置父进程死亡信号，信号仍是 `SIGINT`。调用改为 `syscall(SYS_prctl, PR_SET_PDEATHSIG, SIGINT)`。`getppid` 与记下的父 pid 不一致时仍 `_exit(0)`。关 fd 循环、`sigaction`、`sigprocmask`、`chdir`、`execve` 参数，以及 `fork` 前的环境块保持原样。

两处 `nvidia-smi` 在父进程共用 `resolve_nvidia_smi_path`：读 `PATH`，未设置时用 `confstr(_CS_PATH)`，空字段表示当前目录，`access(X_OK)` 失败则继续，取第一个成功项，相对路径先变成以 `/` 开头的绝对路径。子进程只对这个路径 `execve`，环境指针用当时的 `environ`。两处查询串字节内容不变。找不到可执行文件时不 `fork`。`query_nvidia_smi` 仍返回 `available=false` 的空快照，3 秒截止、超时 `SIGKILL` 和 `waitpid` 不变。采样器仍是 3 秒读截止和阻塞 `waitpid`，三句首次日志原文不变；找不到时返回空串并打现有的 offline 日志。

模型推理热路径没有多一次图像拷贝或预处理。这次只改拉起窗口里的 `prctl` 和 `nvidia-smi` 的 `exec`。`PATH` 遍历在父进程、每次探测一次。模型进程的 `execve` 文件参数仍是绝对路径，argv 第 0 项仍是可执行文件名。

挂起白盒仍把睡眠 60 秒的假 `nvidia-smi` 放在 `PATH` 最前。`available` 仍为 false，耗时大于等于 250 毫秒且小于 2000 毫秒。
