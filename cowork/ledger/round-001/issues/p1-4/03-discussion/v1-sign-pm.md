# 第3步签字

- 问题: P1-4
- 方案版本: v1
- 结论: 不同意
- 条件: A1 删掉「或等价」：两份 `deployment` 架构图里客户端到 gateway 的边，标注必须含字面 `POST /v1/models/{id}/infer`。A4 的 OCR 判定只看 JSON 示例里的键名：该示例对象/数组元素不得出现键 `text`；正文写「禁止 text / 识别字段」不算失败。
- 理由: 使用者是按必读文档写 SDK 的对接人，冻结条目要的是单一推荐路径和四类 `results[].data` 可在文档内核对。A1–A6 已编号且不启服务可查，范围也落在已有 gateway `/infer` 与 OCR 仅检测边界上。但 A1 允许「或等价」时两个人会对 mermaid 标法得出不同对错；A4 把「该 OCR 示例块不得出现 `text`」写成整段禁词，正确写「不要有 text 键」也会被判失败。这两处补进正文后才能黑盒签字。
