## 行为变化
`run_one_point` 的四次 `_metric_series` 第三个参数改为同一次 `server_listen` 返回的 uri。调用 `_hist_delta` 前，before 为空时传入 `{"buckets": [], "count": 0.0}`，after 为空时仍传入空值。`_hist_delta` 函数体、`_metric_series` 正则、`assess_point`、`pick_w_star`、写 pack 规则、默认 30 秒才写 pack、拒绝写入 `conf/server` 和 `conf/packs` 都没有改，也没有在 `run_load` 之前另发推理。

`scripts/server/http_infer_rps.py` 在已经读到的 HTTP 200 响应上解析顶层数值 `server_time_ms`，打印并写入 `--out` JSON 的 p50。缺字段、嵌套字段、布尔和非有限值不进入 p50。

`scripts/coverage_http_report.py` 按锁定顺序准备、calibrate、拉起并压测。进程 worker 数只准备从官方压测完成响应后、进程仍在时的 `mortred_workers_available` 与 `mortred_workers_busy` 之和写入。某个 id 因已提交条件没有写出 worker_nums 与 decode_auto 时，除允许空白的 libface 外以非 0 退出，不留下可勾销清单。本次就走了这条路径。

推理服务热路径没有改。`serve_process` 的 `set_model`、`product_static_bs1`、TensorRT execution context 和 gateway 阶段计时都没有动。`server_time_ms` 在压测客户端收到响应之后解析，现有服务路径够用。这次官方压测没有跑到。
