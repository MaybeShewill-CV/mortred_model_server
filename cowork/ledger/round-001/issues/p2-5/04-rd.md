## 行为变化

`tokens_usable_for_listen` 在绑定端口之前判定。顺序是：metrics token 为空，或与已设置的推理 token、管理 token 相同，仍用原来的拒绝和原来的两句日志；然后拒绝推理 token 缺失、管理 token 缺失、二者相同。三个都非空且两两不同时通过。未设置和空字符串都算缺失，比较是整串相等，短于 32 字符的非空值可以通过。已加载的 `conf/api_keys.toml` 不跳过这次判定。

直接启动 `mortred-gateway.out` 时，失败向 stderr 写 `mortred-gateway: refusing to start: ` 加上对应原因短语，退出码非 0，不出现 `mortred-gateway listening on`，日志不写 token 的值。通过时出现现有监听日志。

`spawn_locked` 在 `exec` 之前、在「executable not found」之前用同一判定。失败不 `exec`。错误字符串含同一原因短语，并带现有前缀 `gateway scrape token rejected:`，`__gateway` 为 `failed`，不进入 `backoff`。`SupervisorApp` 对空 `MORTRED_API_TOKEN` 仍拒绝启动；这三种 gateway token 问题不使 supervisor 主进程退出。gateway 二进制存在且判定失败时，管理面仍启动，提示含同一原因短语。

热路径未改。判定是启动前的几次字符串比较，发生在绑定端口之前。监听之后的 Bearer、API key 和限流仍走现有路径。
