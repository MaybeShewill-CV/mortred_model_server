# 第3步确认

- 问题: P2-6
- 方案版本: v3
- 结论: 不同意
- 条件: 标准 6 只看这份 json。顶层有整数 `sample_interval_ms`，值是 1；没有这个键或值不是 1，标准 6 不通过。`models_gone` 与 `gateway_gone` 各有整数 `elapsed_ms`，从发出 SIGTERM 到该次采样的毫秒。`gateway_gone.elapsed_ms` 减去 `models_gone.elapsed_ms` 的差大于等于 0，并且小于两处 `sample_index` 之差的 50 倍。没有 `elapsed_ms`、差为负、或差大于等于序号差的 50 倍，标准 6 不通过。`models_gone` 上 `yolov8s_alive` 与 `libface_alive` 仍是 false，`gateway_alive` 与 `supervisor_alive` 仍是 true；差大于等于 0 不代替这一拍，没有这一拍标准 6 不通过。`models_gone` 另有整数 `established_to_8080`，值是 0，表示这一拍本机 `127.0.0.1:8080` 上已建立的 TCP 连接数是 0；大于 0 标准 6 不通过。这次验收不另取进程号，也不另查连接。实跑不对 `127.0.0.1:8080` 保持一条不发请求的 TCP 连接，也不用别的客户端等待把 gateway 的退出拖长。标准 7 不因 `elapsed_ms` 或 `established_to_8080` 失败；这两个对象仍然不写 pid；json 仍然不另含这两次采样之间的采样。
- 理由: 验收标准 1 至 5 与标准 7 已编号，同一次可以判定。标准 1 仍是交付后的 `python3 scripts/stop_order_record.py --check`：退出码 0，标准输出恰好七行，第七行之后没有空行，也没有其他标准输出；`logs/stop_order_yolov8s_libface.json` 在命令前后都不存在；同一次打开的单元在 `[Install]` 之前只有一行 `KillMode=process`，等号两侧没有空格，`KillSignal=SIGTERM` 与 `TimeoutStopSec=120` 保持原文，没有 `ExecStop=`。后四行是这次标准输出里的四句固定文字。`--check` 退出码 0 单独不表示驻留进程已经按顺序退出。标准 5 只看这份 json 里的 `signal`、同一个正整数的 `signal_pid` 与 `supervisor_pid`，以及三份等于该整数的 `ppid`，全文不出现 `systemctl`。标准 7 只看 `gateway_gone` 与 `after_supervisor` 的布尔值和更大的 `sample_index`；没有这两次之间的采样，并且这两个对象没有 pid 键，即按该条通过。标准 6 打开 json 能看到两个模型布尔值为 false、gateway 与 supervisor 为 true、`gateway_gone.sample_index` 更大。已发生的空连接实跑也是这一组值：`models_gone.sample_index` 为 3，`gateway_gone.sample_index` 为 4。这份 json 没有采样间隔，也没有这一拍上 `127.0.0.1:8080` 的已建立连接数。间隔 1 毫秒，以及不保持一条不发请求的 TCP 连接，写在做法和「RD 不得自行决定」里。同一次只打开这份 json，标准 6 可以通过，同时确认不了这一拍是 1 毫秒采到的约 2.2 毫秒空载窗口。
