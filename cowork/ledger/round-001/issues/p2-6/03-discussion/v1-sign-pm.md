# 第3步确认

- 问题: P2-6
- 方案版本: v1
- 结论: 不同意
- 条件: 标准 1 同一次只跑交付后的 `python3 scripts/stop_order_record.py --check`，退出码为 0。标准输出恰好是这七行，每行以换行结束，第七行之后没有空行，也没有其他标准输出：`KillMode=process 为通过`、`KillSignal=SIGTERM 为通过`、`TimeoutStopSec=120 为通过`、`模型先退出且当时 gateway 与 supervisor 仍在为通过`、`gateway 先于任一模型消失为不通过`、`模型消失时 supervisor 已退出为不通过`、`gateway 退出后模型 pid 再次出现为不通过`。跑该命令之前 `logs/stop_order_yolov8s_libface.json` 不存在，命令结束后该路径仍不存在。同一次打开 `deploy/mortred-supervisor.service`：`[Service]` 在 `[Install]` 之前有且只有一行 `KillMode=process`，等号两侧没有空格；`KillSignal=SIGTERM` 与 `TimeoutStopSec=120` 两行保持原文；没有 `ExecStop=`。这次验收不改单元文件再跑。后四行是这次标准输出里的四句固定文字。`--check` 退出码 0 单独不表示驻留进程已经按顺序退出。标准 5 只看这份 json：`signal` 为 `SIGTERM`；`signal_pid` 与 `supervisor_pid` 是同一个正整数；`ppid` 的 `yolov8s`、`libface`、`gateway` 都等于这个整数；全文不出现 `systemctl`。验收不再另取发出信号时的进程号。标准 7 只看 `gateway_gone` 与 `after_supervisor` 这两个对象。`gateway_gone` 的 `yolov8s_alive` 与 `libface_alive` 都是 false。`after_supervisor` 的 `supervisor_alive`、`gateway_alive`、`yolov8s_alive`、`libface_alive` 都是 false，且 `sample_index` 大于 `gateway_gone.sample_index`。这四个布尔值表示标准 3 记下的那四个 `pid` 在该次采样是否仍在，对象里不重复写 pid。json 不另含这两次采样之间的采样。
- 理由: 验收标准已编号。标准 2、3、4、6 一次打开标准输出和 `logs/stop_order_yolov8s_libface.json` 就能判定。标准 3 沿用现有 `GET /api/v1/status`：`yolov8s` 与 `libface` 各取 `servers` 里一个对象，gateway 取键 `gateway` 且 `id` 为 `__gateway`；三处 `ready` 为 true，`state` 为 `running`，`pid` 为正整数并等于 `pids`。标准 4 的 pack 全文只有这两节。标准 6 要求两个模型先不在，当时 gateway 与 supervisor 仍在，随后 gateway 与两个模型都不在，且 `gateway_gone.sample_index` 更大。驻留集是这次临时 pack 的 `yolov8s` 与 `libface`。本机没有 systemd 时，实跑向自己拉起的主进程发 SIGTERM，退出码仍按标准 2 为 0。这覆盖锁定句里模型先退出、gateway 随后退出、gateway 退出后模型进程不再存在。现有有序退出、token 和每个 worker 的 TensorRT context 不在这七条的通过条件里。标准 1、5、7 各有一句同一次验收确认不了。标准 1 还写单元文件缺少 `KillMode=`、值不是 `process`、出现第二个 `KillMode=`、`KillSignal` 不是 `SIGTERM`，或 `TimeoutStopSec` 不是 `120` 时，不打印七行且退出码不是 0。同一次验收跑的是交付后的单元，这五种文件没有出现在这次命令里。「前三行来自仓库文件」「后四行来自脚本内的固定样例，实跑不读这些样例」从那七行标准输出看不出读的是哪一份。标准 5 在 `signal_pid` 等于 `supervisor_pid` 之外，还要等于发出信号时那个主进程的 pid。记录里没有第三个进程号，停止完成后该进程已经不在。打开这份 json 时，两个数相等可以判通过，对不上外部进程号也可以判失败。标准 7 写这四个布尔值看的是标准 3 记下的四个 pid，并写 gateway 已消失之后直到 supervisor 消失，两个模型 pid 都不再变成 true。三份采样对象只有 `sample_index` 和四个布尔值，没有再写 pid，也没有这两次之间的采样。打开同一份 json，可以按这两个对象上的布尔值通过，也可以因为中间采样不在文件里而判不了。
