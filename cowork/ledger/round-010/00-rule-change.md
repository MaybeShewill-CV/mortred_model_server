# 口径变更

- 日期: 2026-09-30
- 生效轮次: 10

用户把出口从「综合分大于 8.5 且 P0、P1 为空」改成「九个模块的劣势都是无」。综合分只作记录。

交付范围内的劣势全部进入实现队列。不够 P0 或 P1 的编号为 D-1、D-2。不计毛病不进队列：`docs/unsupported-boundaries.md`（含 HTTP OCR 不识别）、一个 catalog id 一个进程、超时后析构再靠外层 SIGKILL、训练/标注/多云、无交付损失就推翻 HTTP 或后端。

没有固定轮次上限。本轮复审后的劣势集合相对本轮起点一条都没减少，才停止。

第 9 轮在旧出口下停止，核算分 8.4。第 10 轮从第 1 步按新口径重打分，不把第 8 轮劣势原文直接送进队列。
