## 缺陷

无。两点说明（均不计为缺陷）：
1. `mortred_waiting_jobs` 快照早于递减、gauge 永回不到 0 —— 属**另行裁决项**（已记入 `discovered.md` 与本轮 `08-writeoff.md` 的 N-1），按编排方指令不计入 P1-5；QA 的独立源码复核与 RD 判断一致。
2. 任务书 A5 里 `grep -rn 'model_run_timeout' conf/server | wc -l` 的期望值"5"是编排方笔误（5 指原先显式写 0 的配置份数），实测 **44**，不构成缺陷。

## 不适用

- **并发/竞争条件**：本改动是解析期纯函数内的常量替换，解析在启动前单线程同步完成，未新增共享可变状态、锁、线程或回调；既有 `<=0` 早退分支的死代码化不引入新并发路径。
- **序列化/持久化格式兼容**：只改头文件常量、配置文本与文档，未触碰任何 schema/存储格式，无迁移或版本兼容面（`server_config_schema.h` 键白名单未改，确认 0 命中）。
- **时区/本地化/时间格式化**：日志为常量拼接的纯 ASCII，无日期/时区/locale 分支。
- **平台差异**：`timeout_ms / 1000` 与 `(timeout_ms % 1000) * 1000000L` 为整数运算，无常量溢出或符号性问题。
- **模型精度/大模型/多模态**：不涉及前向计算、权重或输入模态；e2e 用 fake worker 验证超时契约，`weights/` 未参与。

## 残余风险

1. **"夹到 500ms"护栏未经变异实验反向验证**：护栏机制在代码与算术上确凿（常量若为 500，`fake_delay_ms=1000` 必 504、`EXPECT_EQ(200)` 必红），但未做"把常量临时改成 500 重跑"的变体实验——测试文件受保护，`server_runtime_config.h` 在被测文件面内，故"该行真的会红"属静态推证而非实测。
2. **A4 判据由替代证明覆盖，两个 gauge（`mortred_waiting_jobs`/`mortred_queue_depth`）的可观测性缺陷本身仍未修**：任何依赖该 gauge 的告警/看板（含"队列积压"类）仍会被钉在 1 或最后一次在飞数，需由新条目处理。
3. **夹值的三处下游连带语义未经针对性断言**：`ewma_seed_ms` 由 1s 变 300000ms（这 5 个 id 的 Retry-After 随之改变）、worker_pool 的 stuck 阈值由 `3*0=0` 变 `3*300000=900s`（顺带修掉一个隐性缺陷）、batch_collector 的 worker 等待由 `wait_ms=-1` 无界变 300000ms 有界；三者只由"常量已改"间接锁定。
4. **未跑本 worktree 的全量测试集**：只按验收构建并运行了两个目标；两构建目录共享 `_bin` 的陈旧产物歧义已用 `touch` 强制重编译消除（重编译后 A1/A2 均绿）。若其它测试也读 `model_run_timeout`，本次未覆盖。
