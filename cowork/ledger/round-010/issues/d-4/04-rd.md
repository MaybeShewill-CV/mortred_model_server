## 行为变化

LightGlue 的 `classify_extractor_outputs` 与 `classify_matcher_outputs` 在返回成功之前扫描已经在宿主内存里的 f32：`scores`、`descriptors`、`mscores0` 出现非有限值时回 `MODEL_OUTPUT_CONTRACT_FAILED`。这两处分类仍由 `extract_feature_points` 与 `match_feature_points` 先调用，因此拒绝发生在分数阈值比较之前。`scores`、`descriptors`、`mscores0` 不是 F32，以及 `matches0` 不是 I32，仍走原有 dtype 分支，回 `MODEL_OUTPUT_CONTRACT_FAILED`。缺 `keypoints` / `scores` / `descriptors` 或 `matches0` / `mscores0` 仍是 `MODEL_EMPTY_OUTPUT`。

CLIP 增加 protected 入口 `classify_embedding_output`。`encode_image` 与 `encode_text` 在对应 session 成功返回之后调用它，写入 embedding 与 `normalize_embedding` 都在其后。入口检查名为 `output` 的张量：F32、秩 2、形状 `[1, D]` 且 `D > 0`。错 dtype、`quiet_NaN`、`+infinity` 回 `MODEL_OUTPUT_CONTRACT_FAILED`，且 embedding 被清空后不再写入。有限且合约的张量回 `OK`，embedding 等于读出的 f32，不做归一化。入口不要求 init，也不打开 session。有限全零仍由后面的 `normalize_embedding` 走原来的 `MODEL_EMPTY_OUTPUT`。

热路径只多一次对已有宿主 f32 的有限性扫描，不复制第二份权重，也不增加色彩往返或预处理。CLIP 成功时仍只把读出的 f32 写入 embedding 一次。
