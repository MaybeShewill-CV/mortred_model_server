## 行为变化

1. **每个被管子进程自成进程组（`pgid == pid`）**：子侧 `::setpgid(0, 0)` 位于 fd 关闭循环之后、`prctl`/`getppid` 复查/`sigprocmask` 之旁、`execve` 之前（async-signal-safe，**ST5 仍成立**）；父侧在 `fork` 返回后立即 `::setpgid(pid, pid)`，容忍 `EACCES`/`EPERM`/`ESRCH`。两侧都调以消除竞态。
2. **7 处投递点全部改为整组投递**（`killpg`），仅 `pgid <= 0` 回退单 pid：`stop_server` 的 SIGINT 与 SIGKILL 升级、`fail_missing_server_uri_locked` 的 SIGKILL、`perform_ordered_shutdown` 的 models SIGINT/SIGKILL 与 gateway SIGINT/SIGKILL。
3. **grace 预算按"整组"计算**（`reap_group_with_grace`）：组长退出后若组内仍有存活，把同一 grace 预算的剩余部分给整组；预算结束仍存活则整组 SIGKILL。组长超时的原触发条件保留（`pgid<=0` 回退路径与原行为一致）。升级后用 `process_group_gone()`（`killpg(pgid,0) == -1 && errno == ESRCH`）确认整组消失；若 grace+2s 后仍未消失，**写一条日志**而不是默认宣称已停止。
4. **语义变化（方案已预期）**：子进程不再属于 supervisor 的前台进程组，终端 Ctrl-C 不再直达子进程，子进程只经两阶段关机收到 SIGINT；models 先 / gateway 后的顺序不变。
5. `test/fake_model_server.cc` 新增 `--spawn-grandchild` / `--grandchild-ignores-sigint` 及同名配置键（supervisor 决定 argv，测试无法加 flag，故配置键是必需路径）。孙进程**刻意不调用 `setpgid`**（留在组长组内），打印 `fake grandchild pid=<n> pgid=<n> ignore_sigint=<0|1>` 后关闭 stdout/stderr（该模式测组回收，不测日志管道所有权）。

## 新增问题

1. **`process_group_gone` 把僵尸成员也算"存在"，孤儿孙进程依赖 PID 1 回收**：本机 PID1 = systemd，实测孙进程被 SIGKILL 后 100ms 内 `ESRCH`；若某环境 PID 1 不回收孤儿（例如测试进程即 PID 1 的容器），日志确认会延迟或报 "survived grace+2s"——不影响 supervisor 的停止语义，只影响确认与日志。QA 若在容器内跑需注意该边界。
2. **stop 的 grace 现按组计算**：存在"故意慢退出的孙进程"时，stop 在组长退出后最多再等剩余 grace 才升级（不会提前杀），总时长上界仍为 grace+2s。
