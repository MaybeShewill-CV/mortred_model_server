## 缺陷

无。**并附两条非阻塞发现**（未计为缺陷，A1–A5 判定不受影响）：

1. **packaged 证据缺口**：`packed_batch_nvi_unittest` 在 `build` 与 `build-full` 都无法链接（`undefined reference to gpu_jpeg::GpuDecodeSlot::open()/~GpuDecodeSlot()`），根因是该目标的 `link.txt` 只链 `../_lib/libcommon.so`、没有 `libmodels.so`（符号在 `libmodels.so` 里，与第 6 轮审计记录的不可链接目标一致）。与本提交无关（提交不含任何 CMake 文件，也未碰 `backend_cv_model.h`/`gpu_jpeg_decoder.cpp`），该二进制在 QA 操作前就不存在。后果：`BackendCvModel::run_batch` 那道 packed 栅栏只做了代码走查，未做动态验证。
2. **设计里的调用点数偏小**：设计写"12 个 `data<T>()` 生产调用点"，实测 **23 处**（`.data<T>()` 与 `.template data<T>()` 合计，`src/` 内、排除 `tensor.h`），分布在设计点名的同一批 9 个文件；`Tensor::make` 实测 24 处与设计一致。这只让"否决 log+nullptr 方案"的理由更强，不影响验收。

## 不适用

- **catalog id / 未就绪模型**：不适用。只改 host tensor 的 shape/dtype 契约，不触及模型解析、catalog、`ready`。
- **空输入 / 极端尺寸 / 通道色彩约定**：不适用。改动在张量契约层，不经过图像输入路径（`from_mat` 惯例未动并有既有断言）。
- **输出结构 / 坐标 / mask / 分数值域**：不适用。未改任何解码或后处理；`object_detection_output_contract_unittest` 13 例作为形状不变量证据。
- **跨后端可比结果**：不适用。`Tensor` 契约与后端无关；本次为 cpu profile。
- **golden + CI**：适用且成立。5 个目标均为 ctest 注册用例（`build-full` 共 96 个），`ci.yml` 跑 `ctest`。

## 残余风险

1. `packed_batch_nvi_unittest` 不可链接（既有问题）导致 packed 批量栅栏缺少动态验证，只有代码走查；该二进制在本次操作前即不存在。
2. `backend_unittest` 的 5 例 SKIPPED 源于权重/GPU 缺失（MNN/ONNX 权重），A4 只要求 exit 0，已满足；但跳过项本身不构成对 `Tensor` 契约的覆盖。
3. 结论只覆盖设计点名的 5 个目标；未跑整仓 ctest（该 worktree 的整仓测试面存在既有的不可链接目标，见第 1 条）。
4. 白盒 fence 的第三条证据（`fence_proof`）是 QA 在 `/tmp` 临时编译的探针，不在 CI 中；若需长期回归，可考虑把该断言并入 `tensor_contract_unittest`（本次不改，因受测文件不可改）。
